# 文献工作台网页版本设计

日期：2026-10-15。状态：设计讨论稿，待用户评阅；不是已实现功能清单。配套可点击草图仅用于确认布局与交互。

## 1. 目标与依据

让用户在浏览器完成批量导入、文字识别、跨文献检索、原页核对、摘录整理与报告输出。日常工作以网页为入口，现有 Python 文献处理核心继续复用。优先解决提取、识别和检索。

用户已确认：本地优先、团队其次；支持自己的 AI API；主要处理建国后现代横排中文县志、丛书及 Word。2026-10-15 用户明确规模为 **3–5 份 PDF 合计 1000 页**，取消此前建议的“单份 300 页、合计 1500 页”口径；1000 页是验收目标，不是已经测得的能力。

前期检查过的真实节选位于 `<本机资料目录>`，当时为 6 份 PDF、2 份 DOCX，PDF 共 91 页；其中 5 份没有文本层，1 份有文本层。样本有单栏、双栏、较淡字迹、文件页序与印刷页码不一致。抽样 OCR 出现过页码错误，因此置信度不等于准确率。这些样本支撑版面与质量设计，不能替代 300 页长文档测试。

现有首版实现了导入、OCR、摘录版本与任务恢复、报告导出；检索仍为 SQLite LIKE 字面匹配。尚无正式网页、专用全文索引、持久化 OCR 队列或 1000 页性能验收。

## 2. 产品范围与我的设计决定

- 形态：单用户本地网页，启动器打开浏览器；原件、索引和研究记录在本机。远程模型仅在用户发起研究时使用。
- 首版以桌面浏览器为主，兼容小屏查阅；参考基准为 1440×900、1024×768、390×844。
- 默认进入全库检索；空库显示导入引导；恢复上次查询、选中文献与阅读位置。文献库承担资料管理，研究项目承担专题组织。
- 视觉方向：用户否定暖白/松绿的初稿，明确要求直接按 Notion 工作区样式重做。采用浅灰侧栏、纯白主区、系统无衬线字、页面大标题、面包屑、数据库视图栏、低边框表格与右侧预览；不再混用 Apple/LINER 的视觉方向。界面保留自身工作区名称。
- 首个真实闭环为导入→识别→索引→检索→核对→摘录→导出。AI 研究随后接入同一套证据。
- 团队账号、云端托管、多人协作、向量检索、模型训练和复杂表格结构还原留待后续；扫描图、表格图像保留供核对。

## 3. 导航与页面

侧栏工作区名称为“个人图书馆”，按工作区/专题分组，使用图标加文字导航：全库检索、文献库、识别任务、摘录集、研究项目、设置。去掉 01–06 序号导航。顶栏为面包屑和简洁操作，正文使用独立大标题与简短描述。ID 和哈希放在详情中按需展开。

| 页面 | 核心问题 | 主要操作 |
| --- | --- | --- |
| 全库检索 | 哪本书、哪一页记载了它？ | 查询、过滤、翻页、打开原页、保存摘录 |
| 文献库 | 资料是否导入，信息是否齐全？ | 批量导入、编辑书目、打开文献、查看状态 |
| 识别任务 | 处理到了哪里，哪些页失败？ | 暂停、继续、重试失败页、查看异常页 |
| 摘录集 | 哪些材料可用，哪些还需核对？ | 分类、备注、审核、回到原文、导出 |
| 研究项目 | 专题使用哪些资料，已有何种证据？ | 选文献、设问题、选方案、运行或恢复研究、导出报告 |
| 设置 | 本地资源与 AI 如何使用？ | OCR 并发、模型地址和密钥、方案配置、备份位置说明 |

### 3.1 全库检索：主工作界面

桌面分为浅灰导航、命中列表、右侧原页预览。1440px 宽时建议导航 240px、结果列表约 310px，余下空间留给原页。搜索区按 Notion 页面组织：32px 大标题、简述、视图栏、36px 高搜索框和轻量筛选，避免多层说明框。分隔线可拖动，最小宽度保护正文可读性；AI 抽屉默认收起，窄屏打开时覆盖而不挤压原页。

搜索栏支持中文短词、精确短语、全部包含和任一关键词；高级条件折叠，初次使用只需输入词并搜索。精确检索与别名扩展分别标识，扩展词可见且可取消。首版不把语义相近当作原文命中。

结果按文献分组，提供总命中文献数、命中页数与结果分页。默认每页 30 条；每条显示书名、文件页序、印刷页码、原文片段、文本版本与核验提示。片段使用安全的文本节点高亮，不解释原文 HTML。选中结果切换阅读区并保持查询和列表滚动位置。

覆盖提示始终可见。例如“PDF 已覆盖 88/91 页，3 页待处理；Word 已索引 2/2 份”。覆盖指当前版本已索引的文字页加人工确认的空白页，不能把待处理或失败页算入。低置信度但已入索引的页可搜索，同时显示待复核；识别完成和人工核验是不同状态。页数尚未知时显示“正在统计页数”，不能显示 0/0 或假百分比。

没有命中时，显示查询条件与覆盖范围，并提供修改词、扩展别名、查看待识别页的入口。旧查询返回较慢时不能覆盖用户的新查询结果。

分页采用“发现更新则重新查询第一页”的规则，不保留旧索引快照。第一次查询返回 index_revision，后续分页携带 expected_index_revision；代次不一致返回 HTTP 409/SEARCH_INDEX_CHANGED，前端保持条件并自动刷新第一页，同时说明资料更新。文字进入 dirty、索引完成、文献增删或会影响搜索显示的书目/页码变更，都在同一写事务增加代次。结果、总数和覆盖来自同一数据库读事务；不能分别读取后拼成看似一致的结果。

### 3.2 阅读与核对

阅读区有“原件”“识别文字”“对照”三个视图。默认原件。只加载当前页及相邻页，缩略图按需请求；切换结果时取消旧请求，过期响应不能换错页。原页缩放、适宽、上一页/下一页、文件页跳转均有明确按钮。

常驻来源栏分开显示“文件第 7 页 / 共 12 页”与“印刷页码 775”。后者可为未确认、候选或已确认；识别出候选页码不会自动视为正确。节选文件的页序不能直接当成原书页码，也不能仅用统一偏移推断所有页面。书名、编者、出版年、版次、卷次可从书目抽屉编辑。

OCR 提供真实行框时，文字行可定位到扫描图中的对应区域；缺少坐标时只定位到页面并明确范围。文字 PDF 当前只有页级定位，不伪造字框。双栏阅读顺序要单独验收，未能可靠恢复时保留原始顺序并标记待核；不悄悄把左右栏逐行拼接。

“识别文字”保留原文换行，可选择文字保存摘录。“对照”用于扫描与文字并排检查；小屏切换显示。编辑进入明确的校订状态，展示原文和修订差异，填写原因后保存。校订中离开先询问是否保留草稿。服务端按版本哈希检查并发变更，返回冲突时保留草稿并要求重新核对。

保存摘录弹出小型编辑面板：逐字引文、来源、分类、备注、所属摘录集/研究项目。系统保存的偏移必须指向当前选择的那一次出现。跨页材料拆成多条证据归入同一摘录集，不伪造一个跨页文字偏移。

DOCX 使用独立的逻辑文档视图，默认显示按原文顺序排列的段落/表格及选中单元，提供“文档文字”“校订对照”“书目与原件”。段落和表格显示单元序号及标题路径，前后文按单元加载；校订对照只比较原提取文字和校订文字。“下载原件”供用户在 Word/WPS 打开。首版不增加 Word 格式转换或固定版式预览，也不显示 PDF 页码或伪造的扫描图。

### 3.3 文献库与导入

使用紧凑列表：书名/文件名、类型、页数、处理状态、索引覆盖、书目完整情况、最近处理时间。长文件名有完整查看入口；同名书以编者、版次、卷次区分，操作依据稳定文献 ID。

导入支持多文件选择、拖拽及选择目录；目录选择仅接收浏览器实际选择的文件集合，不让网页任意读取服务端路径。导入分上传到本机、校验/去重、统计页数、文字提取/OCR、建立索引几个阶段。重复文献关联已有记录，可补做未完成页，不复制成第二本。

浏览器上传进度与 OCR 进度分开。OCR 不阻塞上传请求或页面切换；浏览器关闭后，本机服务仍运行时任务继续，服务退出后重新启动可恢复。真正需要停后台服务时由启动器控制并说明影响。

### 3.4 识别任务

列表显示任务状态、所属文献、已处理/总页数、可检索页数、失败页数、处理方式。点开任务查看逐页列表及错误原因。资源默认单个 OCR 工作进程，可在设置中调整；前台阅读与 OCR 使用独立执行环境，避免后台占满界面。

状态为排队、准备中、处理中、正在暂停、已暂停、部分完成、完成、失败。暂停在当前页的安全提交点生效；不能只停止前端进度条。重试失败页不重做成功页。识别为空的页面先标记待确认，人工可确认为空白；错误不会被自动抹成成功。

坏文本层或已完成页也可从阅读器/文献详情发起“重新识别”，明确选择当前页、页范围或整本文献；这是独立任务，区别于失败重试与重复导入。用户确认后，force 会重做所选 completed 页。原件不动，旧识别写入历史，现有人工校订保留且提示复核，不自动用新 OCR 覆盖人工文字。旧原文证据按版本变化进入需复核；校订与历史引用不会因重识别丢失。新结果提交前仍显示旧版并标“重新识别中”，提交后原子更新版本/dirty/代次；校订版不匹配新行框时降为页级定位。

### 3.5 摘录集与成果

列表支持按文献、分类、项目、核验状态筛选，批量分类、移动到摘录集和导出。核验状态使用中文标签并配符号：待核验、已接受、已拒绝、需复核。颜色只作辅助。

每条摘录保留原文、分析备注与来源；编辑分析不会改写引用。打开详情可以查看所引版本和历史。原文校订后旧摘录的“需复核”状态同步到列表和引用它的报告；摘录已接受不表示报告结论已确认。

导出提供证据 CSV/JSON 与报告 Markdown/JSON/DOCX。先显示格式、范围和核验提示，再下载文件；不让用户输入服务器任意输出路径。首版报告支持整理和导出，复杂排版编辑器留待后续。

### 3.6 研究项目与设置

项目记录问题、选用文献、方案、摘录和报告。AI 研究在用户确认资料范围后启动；整个 search/read/excerpt/finish 过程都受同一文献范围约束。范围、分类、别名、提示词与输出章节在启动时快照保存。任务进度显示“检索、阅读、保存证据、形成报告”等实际动作及结果，不把模型不可观测的思考当成日志。

模型未配置时，检索、识别和人工摘录正常使用。设置通过网页填写兼容接口地址、模型和密钥；密钥默认只在本次服务运行的内存中使用，环境变量仍可作为兼容入口。可选系统凭据保存由执行阶段按平台能力决定，不能退化成写入 TOML 或浏览器 localStorage。界面只返回“已配置”，不回显已保存密钥。服务重启后内存密钥需要重填，任务检查点仍在。

保留明显的键盘焦点。Enter 搜索，Ctrl/Cmd+K 聚焦全局搜索，Esc 关闭抽屉或对话框；不接管浏览器原生查找。动效仅用于状态切换、面板展开，约 120–180ms，并尊重减少动态效果偏好。状态变化以 aria-live 通知，不能每一页 OCR 都播报一次。

1024px 时侧栏可缩为约 200px，保留文字；850px 以下使用明确的菜单入口和可收起侧栏，结果列表→阅读详情单栏切换，返回时保持查询和滚动位置。小屏触控目标约 44px；页面不应出现整体横向溢出。PDF 放大后的内部滚动是阅读器功能，不以缩小所有文字解决布局。

## 5. 实现建议与接口边界

我的建议是 React + TypeScript + Vite 前端，FastAPI 本地接口，复用 Python 核心和 SQLite。发布时把前端编译产物随 Python 包分发，用户无需安装 Node；开发时才需要前端工具链。首先用现有按页渲染图片构建阅读器，OCR 框作为真实坐标覆盖层；将来需要更完整 PDF 文本选择时再评估 PDF.js。

OCR 使用持久化队列与受控子进程，网页请求只创建任务并读状态。PDFium 不允许不同线程同时调用，因此渲染与识别并发采用隔离进程或明确串行执行。队列保存在 SQLite，具有任务租约、检查点和恢复规则；单个任务同时只有一个执行者。

本地全文检索采用 SQLite FTS5 的**字符位置编码索引**作为首版建议：对既有去空白归一化后的每个 Unicode 字符产生 `u` 加六位十六进制码点的 token，空格连接后交给 FTS5 Unicode61 tokenizer。查询按相同规则编码，短语由位置约束匹配。这样单字、双字、标点均有明确索引路径；原文仍单独保存并通过映射回查，不拿编码文字展示给用户。首版只去空白，大小写按原始字符精确匹配；如需忽略大小写另做明确选项。多词模式用 AND/OR 组合各自短语。检索排序首版按匹配词数、命中次数、稳定文献 ID 与页序，不依赖字频直接解释“学术相关性”。

索引包含稳定 unit_id、doc_id、文本版本及版本哈希。页面提取/校订成功后创建重建索引任务；索引不对应当前版本时标记 dirty，检索按当前版本回查候选、过滤失效项，并将 dirty 页计入未覆盖范围。手工校订不得导致旧文字继续被当作当前命中。所有结果都能精确定位回原文，不能用向量召回替代字面证据。

Web API 前缀 `/api/v1`，同源提供静态文件。服务默认仅监听 `127.0.0.1`；启动时建立本地会话校验，对写操作校验会话及 Origin。上传文件流式保存到暂存目录，默认每文件上限 1GiB，可在本机设置调整；按稳定 ID 提供原件/页图/导出文件，所有名字作为数据处理。

## 6. 验收与分期

第一里程碑：网页完成导入、后台 OCR、真实索引、检索与原页核对，并能保存摘录。第二里程碑：摘录集、报告导出、AI 研究和模型设置。第三里程碑：打包启动与长文档性能验收。

必须验收：中文和空格路径；单字/双字/短语/标点；双栏阅读顺序；文件页序与印刷页码；无文本层；坏文本层与强制 OCR；重复文件；服务重启；处理中关闭浏览器；失败页重试；旧查询晚返回；校订时版本冲突；任务与模型上下文的文献范围隔离。

计划性能目标：在记录 CPU/RAM/磁盘的验收机器上，对合计 1000 页已建索引文字，固定查询集的检索 API p95 不超过 1 秒，OCR 同时运行时 p95 不超过 2 秒；这是待测目标。页面预览只加载当前与相邻页，不加载全书页图。OCR 耗时和准确率用真实资料测量，不从两页抽样推断；合计 1000 页真实资料缺失时必须标为未完成，不能将节选重复拼接当作真实长书验收。

识别质量基准建议人工标注 12 个代表页（含单栏、双栏、淡字、数字与专名），记录字错误率、阅读顺序错误及给定名称的检索召回。目标数值由首轮基线与用户材料核对后确定，不能预先声称 98% 等准确率。

## 7. 设计草图说明与待反馈事项

`design/web-prototype/index.html` 是经用户同意制作的可点击设计草图，使用两张本地真实扫描样本页展示阅读空间。队列进度、检索结果与 AI 动作均为演示；没有连接文献库或 API，不接收真实密钥，不代表上述后台已完成。

本轮希望用户反馈的是：检索结果与原页的空间分配、原件/文字对照的使用感受、识别队列信息是否易读。具体 CPU 并发、索引压缩与缓存参数留给执行阶段实测，整体视觉与工作流可在草图评阅后修改。
